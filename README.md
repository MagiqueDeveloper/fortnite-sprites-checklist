# Fortnite Sprites Checklist

A basic, print-first **Treasure Hunters** checklist. The page shows the A4 sheet,
with a small toolbar for Found/Mastered totals, Reset, and Print A4. Tick the
Sprites you collect and print the same checklist with your marks.

[Live GitHub Pages site](https://magiquedeveloper.github.io/fortnite-sprites-checklist/)
· [Report a bug](https://github.com/MagiqueDeveloper/fortnite-sprites-checklist/issues/new/choose)
· [Contribute](CONTRIBUTING.md)

The launch roster has **11 families and 31 collectible forms**: ten families with
Base, Fortune and Cursed forms, and Sweet Dreams with Base only. Gold forms are
excluded until confirmed released. Rarities are provisional spawn-tier readings
from [Sprite Catch](https://spritecatch.com/news/treasure-hunters-new-sprites/),
checked 1 November 2026; they are not official Epic rarity confirmations.

## Run locally

Requirements: Node.js 24+, Python 3.12+, and pip for roster tests/sync.

```sh
npm ci
python3 -m venv .venv
. .venv/bin/activate
pip install -r scripts/requirements.txt
npm run dev
```

```sh
npm test           # progress rules, input validation, sync parser, local art
npm run build     # TypeScript validation and Vite production build
npm run preview   # serve dist/ locally
```

## Progress and privacy

Progress is stored on this browser/origin under `treasure-hunters-sprites-v1`.
Mastered implies Found; clearing Found clears Mastered. Stored data accepts only
known Sprite IDs and boolean values. Clearing site data removes your saved ticks.

The app has no backend, accounts, analytics, or AI runtime. It never reads your
Epic account. Progress does not automatically sync across devices. Storage errors
are shown in the interface; ticks cannot persist when browser storage is blocked.

Override progress remains untouched under `ch7s4-sprites-v4`. Its roster is kept
in `src/data/archive/override.json` and its artwork remains in the source tree.
The current interface displays Treasure Hunters.

## Offline and print

All current Sprite images ship locally. Archived artwork stays in Git but is
excluded from the production package and offline cache. Production builds stamp a service worker
with a content hash and precache list. A new worker activates only after its
complete cache is ready, and cleans up only this application's caches. After a
successful first online visit, the app can reopen offline. Clearing site data
removes both offline files and saved ticks. The manifest supports browser install.

Desktop shows the printable sheet immediately. Narrow screens use the existing
compact family layout with larger tap targets. Print A4 and Ctrl/Cmd+P always
produce the complete A4 roster with current ticks.
Serve the build over HTTP rather than opening index.html from a file URL.

## Roster maintenance

```sh
npm run sync-sprites:dry
npm run sync-sprites
python3 scripts/sync_sprites.py --refresh-images
```

The Python script parses Sprite Catch's structured roster table and individual
family pages. It rejects unknown variants, incomplete rosters, and missing art.
Downloads are staged and verified before the data file changes. A dry run writes
nothing. Art is centered on transparent 150×150 PNG canvases. Source details are
in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

The existing Friday 02:00 UTC GitHub Actions schedule opens or updates a roster
pull request after tests/build pass. It does not publish unreviewed roster changes.
GitHub's “Allow GitHub Actions to create and approve pull requests” setting must
permit PR creation. Monthly Dependabot checks cover npm, pip, and Actions.

## Structure

- `src/App.tsx`, `src/components/Toolbar.tsx`: basic controls above the checklist
- `src/data/treasure-hunters.json`: current roster generated by the sync script
- `src/lib/progress.ts`, `src/hooks/useTicks.ts`: validated local progress
- `src/components/Sheet.tsx`, print styles: full A4 checklist
- `public/sprites/`: locally hosted artwork
- `scripts/sync_sprites.py`: roster/art pipeline; `tests/`: regression coverage
- `.github/workflows/`: PR checks, reviewed roster updates, Pages deployment
